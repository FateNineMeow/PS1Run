# 01 需求与验收口径

> 状态横幅：截至 2026-11-24，R1–R6、R9、R10 的代码主体已完成（3 个功能点部分实现），核心逻辑通过 7/7 组自动化测试；R7/R8 两项评估已闭环。注册表实机变更与双击交互等逐条验收保留给人工确认。实现落点见 [02 功能实现清单](02-feature-matrix.md)，差距见 [04 项目进度与差距](04-progress.md)。

## 1. 需求原文拆解

| 编号 | 原始需求要点 | 我的理解（可执行口径） |
|---|---|---|
| R1 | 注册/注销 `.ps1` 文件关联 | 把 `.ps1` 的默认打开程序指向本程序，并可完整回滚到注册前状态 |
| R2 | `.ps1` 的运行方式：编辑、执行、**选择** | 同一个 `.ps1` 既能"用编辑器打开"，也能"用 PowerShell 跑起来"；第三种是"每次双击都弹窗让用户当场选"，适用于混合场景 |
| R3 | 执行程序选择：PS5 / PS7 / 自动（按文件编码选） | 可固定用 PS5.1、固定用 PowerShell 7，或"自动"——读脚本字节流判断编码，再决定交给哪个解释器 |
| R4 | 自动搜索执行程序，不存在时提示用户指定 | 探测链优先，探测失败必须降级为人工选择并记住结果，不能崩溃、不能静默失败 |
| R5 | 编辑程序：尝试常见编辑器默认安装位置，文件不存在时提示用户选择 | 探测链 + 人工选择兜底，且必须能覆盖"装在非默认盘"的情况（本机即如此） |
| R6 | 双击 `.ps1` 打开本程序，按运行方式调用不同程序处理 | 双击 → 本程序（短暂）→ 目标程序。本程序是**分发器**，不是编辑器也不是解释器 |
| R7 | 评估 `.NET 4.8` 与 `.NET 11` 双版本可行性 | 见 [09](09-eval-dual-target-framework.md) |
| R8 | 评估是否需要后台常驻 | 见 [10](10-eval-background-residency.md) |
| R9 | 日志与诊断：记录分发过程、可查看并导出日志 | 分级日志 + 会话/退出码 + 7 天保留；主界面可打开日志目录、查看与复制当日日志 |

## 2. 术语约定

| 术语 | 含义 | 备注 |
|---|---|---|
| **文件关联** | Windows 中"某扩展名 → 某 ProgId → 某命令"的三级映射 | 详见 [06](06-tech-file-association.md) |
| **ProgId** | 程序标识符，如 `Ps1Run.ps1`、`Microsoft.PowerShellScript.1` | 注册表里承载动词（open/run/edit）的节点 |
| **动词（verb）** | ProgId 下 `shell\<verb>\command` 定义的具体动作 | 本项目设计：`open`=按设置（可能弹窗）、`run`=强制执行、`edit`=强制编辑 |
| **UserChoice** | Win8+ 用户对扩展名的显式选择，带不可伪造的 Hash | 会**覆盖** ProgId 关联，是本项目最大技术约束 |
| **运行方式** | **执行（Run）/ 编辑（Edit）/ 选择（Ask）** 三种动作策略 | 对应 R2；"选择"= 每次都弹窗当场选 |
| **执行程序** | `powershell.exe`（PS5.1）或 `pwsh.exe`（PS7+） | 对应 R3、R4 |
| **编辑程序** | 用户偏好的文本编辑器 | 对应 R5 |
| **直通模式** | 带 `--open` / `--run` / `--edit` 参数时不显示主窗口，直接分发（`--open` 在"选择"模式下会弹一个独立小窗） | 对应 R6 的体验优化，见 [10](10-eval-background-residency.md) |

## 3. 逐条验收口径

### R1 关联注册/注销

**验收标准**
1. 执行"注册"后，`HKCU\Software\Classes\.ps1\OpenWithProgids` 中存在 `Ps1Run.ps1` 值。
2. `HKCU\Software\Classes\Ps1Run.ps1\shell\open\command` 指向 `<安装目录>\Ps1Run.exe --open "%1"`（按设置分发，`run` 动词才是 `--run`）。
3. `HKCU\Software\Classes\Ps1Run.ps1\shell\edit\command` 指向 `<安装目录>\Ps1Run.exe --edit "%1"`。
4. 若检测到 `.ps1` 存在指向他处的 `UserChoice`，界面必须明确提示"系统当前默认程序为 X，本程序可能不生效"，并给出引导入口（不得伪造 Hash）。
5. 执行"注销"后，`Ps1Run.ps1` 整棵子树被删除、`OpenWithProgids` 中的 `Ps1Run.ps1` 被移除，且**不破坏**原有的 `VSCode.ps1` 等第三方项。
6. 注销后双击 `.ps1` 不应出现"未知文件类型"或报错。

**边界**：机器级注册（HKLM）作为可选项，失败必须明确提示"需要管理员权限"，不自动降级为仅用户级（与 [06 §6](06-tech-file-association.md#6-权限与作用域) 口径一致）。

### R2 运行方式（三态）

**三种运行方式矩阵**

| 值 | 显示名 | 双击 `.ps1` 时的行为 | 典型场景 |
|---|---|---|---|
| `Run` | 执行 | 不弹窗，直接进入执行分支 | 已信任的脚本目录、批量跑脚本 |
| `Edit` | 编辑 | 不弹窗，直接用编辑器打开 | 以维护/调试脚本为主 |
| `Ask`（**默认**） | 选择 | **每次都弹选择窗**，由用户当场决定编辑还是执行 | 混合场景、刚接触本工具的用户 |

> 默认取 `Ask` 的理由：双击一个未知脚本就直接执行有安全风险，且用户首次使用时需要"看见"本程序在做什么。用户熟悉后可在设置里改为固定的 `Run` / `Edit` 以减少点击。

**验收标准**
1. 右键 `.ps1` 能看到"打开"（等同双击）、"运行"、"编辑"三个显式入口；双击（`open` 动词）按设置中的运行方式处理。
2. 设置界面能三选一：执行 / 编辑 / 选择，切换即时生效、无需重启，并持久化。
3. 运行方式为 `Run` 时不得弹出任何选择窗；为 `Edit` 时不得启动 PowerShell。
4. 运行方式为 `Ask` 时，**每一次**双击都必须弹窗，不得"弹过一次就记住并跳过"（除非用户主动勾选了"以后都这样处理"）。
5. 右键的"运行""编辑"属显式意图，**必须绕过** `Ask`，不再弹窗。

**"选择"模式的弹窗交互位置**
6. 弹窗是一个**独立小窗**（不依附主窗口，因为直通模式下主窗口不存在），定位在**鼠标指针所在显示器的居中位置**（多屏场景不得弹到另一块屏），不在任务栏显示按钮（`ShowInTaskbar=false`）。
7. 弹窗内容：脚本文件名（醒目）+ 完整路径 + 三个按钮 `[执行 (Enter)]` `[编辑 (E)]` `[取消 (Esc)]`，默认焦点在"执行"。
8. 提供复选框"以后都这样处理（不再询问）"：勾选并点执行/编辑后，运行方式分别被改写为 `Run` / `Edit`。

**"选择"模式的取消行为**
9. `Esc`、标题栏关闭按钮、点击"取消"，三者行为完全一致：**不启动任何目标程序、不修改任何设置、不留下进程或窗口**，进程以退出码 `0` 正常结束，日志记一条"用户取消"。
10. 即使用户已勾选"以后都这样处理"，只要最终点的是"取消"，就**不得**写入设置（取消优先，不做任何副作用）。
11. 弹窗**不设自动超时关闭**——超时自动选一个动作属于误操作风险。
12. 极端情况（无交互式桌面会话、窗口创建失败）：不执行任何程序，退出码 `4`，写错误日志，不得静默执行。

**与执行器/编辑器的组合关系**

| 运行方式 | 到达"执行"分支后 | 到达"编辑"分支后 |
|---|---|---|
| `Run` | 由执行程序策略（PS5 / PS7 / 自动）决定解释器，自动模式再走编码判型 | 不涉及 |
| `Edit` | 不涉及 | 由编辑器探测链（四级回退）解析编辑器 |
| `Ask` → 用户选"执行" | 同 `Run` | — |
| `Ask` → 用户选"编辑" | — | 同 `Edit` |
| `Ask` → 取消 | 不启动任何进程，退出码 0 | 不启动任何进程，退出码 0 |

> 关键点：**运行方式只决定"编辑还是执行"，不决定"用哪个版本/哪个编辑器"**。这两层是解耦的，详见 [05 §3](05-architecture-flows.md#3-启动流程) 与 [07 §5](07-tech-powershell-encoding.md#5-自动选型规则)。

### R3 执行程序选择

**验收标准**
1. 设置项提供三态：`PS5` / `PS7` / `自动`，持久化到用户配置。
2. `自动`模式下的判定必须可解释：界面上能看到"本文件被判为 UTF-8，交给 PS7"这类结论（可放在日志或提示中）。
3. 判定规则见 [07 的编码决策表](07-tech-powershell-encoding.md#4-编码判型决策表)，不得出现"文件编码无法识别就崩溃"。

### R4 执行程序探测

**验收标准**
1. 依次探测硬编码路径 → 注册表锚点 → `PATH`；命中第一个即用。
2. 全部未命中时弹窗说明"未找到 PowerShell 7"，并提供"浏览选择 exe"按钮。
3. 用户手选的结果必须持久化，下次直接复用；若该路径后来失效，需再次提示而不是启动失败。
4. 探测逻辑可单元测试（注入文件系统/注册表抽象），见 [02](02-feature-matrix.md) 中 F3.5。

### R5 编辑程序探测

**验收标准**
1. 探测顺序：用户已配置 → 常见安装路径 → `App Paths` 注册表 → `Uninstall` 注册表 → `PATH`。
2. 本机 VS Code 装在 `D:\Soft\Code\VS Code`，必须能被 `HKCU\...\App Paths\Code.exe` 命中——这是本页最强的现实验证点。
3. 全部失败时回退到系统记事本（`%SystemRoot%\System32\notepad.exe`，本机实测存在）；当前代码回退到记事本时不弹提示，仅当连记事本都缺失时才报错。
4. 允许用户在设置中手动指定任意 exe 与参数模板。

### R6 双击分发

**验收标准**
1. 双击 `.ps1` 后，本程序命令行能收到完整文件路径（含空格、中文）。
2. 执行类动作使用脚本所在目录作为工作目录（否则脚本内的相对路径会错）。
3. 目标程序启动后，本程序进程退出，不留后台进程（与 [10](10-eval-background-residency.md) 结论一致）。
4. 目标程序不存在时给出可操作提示，不产生未处理异常弹窗。

### R7 / R8 评估

**验收标准**：给出明确结论 + 依据 + 可执行方案，不写"视情况而定"。已分别落在 [09](09-eval-dual-target-framework.md) 与 [10](10-eval-background-residency.md)。

### R9 日志与诊断

**验收标准**
1. 每次分发都写日志，包含命令行参数、动作判定、编码判型、选中的解释器/编辑器、目标进程 PID 与退出码。
2. 日志按级别（DEBUG/INFO/WARN/ERROR）区分，带会话 ID 与进程 ID；多次双击可被区分。
3. 日志写在 `<软件根目录>\log\yyyyMMdd.log`，按天滚动；保留天数取 `config.json` 的 `LogDays`（默认 7），每天首次运行清理一次；写日志失败不得影响分发。
4. 主界面能打开日志目录、用系统程序查看当日日志、复制最近日志；诊断信息可一键复制。
5. 用户取消、参数非法、文件缺失、目标进程启动失败、未处理异常均须留下可读日志或中文提示，且取消不得启动任何目标程序。

**边界**：本程序是分发器，日志只记录决策与启动结果；**不**持续捕获目标脚本的 stdout/stderr，也不上传日志。

## 4. 明确不做（范围外）

| 不做的事 | 原因 |
|---|---|
| 伪造 `UserChoice` 的 Hash 来强行改默认程序 | Hash 算法未公开，写错会被 Windows 重置；属不可靠且不透明的做法，见 [06](06-tech-file-association.md#3-userchoice-这道墙) |
| 内置编辑器 / 内置语法高亮 | 本程序是分发器，不是 IDE |
| 常驻服务、开机自启、托盘常驻 | 见 [10](10-eval-background-residency.md) 结论 |
| 修改 PowerShell 执行策略（ExecutionPolicy） | 涉及安全边界，最多只做"现状展示与提示"，不主动改系统策略 |
| 支持 `.psm1` / `.psd1` 等其它 PowerShell 文件类型 | 本期只做 `.ps1`，避免范围膨胀 |
| Linux / macOS 支持 | WPF 本身即 Windows 限定 |
